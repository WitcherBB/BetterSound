## 📦 项目简介
### 项目定位
BetterSound 是一款为 Minecraft 1.20.1 开发的 Forge 音效交互增强模组，**由个人独立完成从0到1的需求设计、代码开发、测试上线全流程**。

### 解决的核心痛点
针对 Minecraft 原版存在的两大核心体验缺陷进行深度优化：
1. 原版乐器功能极度单一，仅支持基础音符盒点击，无完整钢琴演奏、延音、乐谱播放等专业音乐交互能力
2. 原版唱片机仅支持单机近距离手动操作，无法实现多设备集中控制、红石信号远程联动，多场景操作效率极低

### 核心价值
为玩家提供高沉浸感的游戏内音乐创作体验，同时优化红石音乐场景的操作效率，兼顾娱乐性与实用性，上线后获得社区玩家广泛好评。

## ✨ 核心功能亮点
### 🎹 88键全音域钢琴系统
- 完整还原标准钢琴88键全音域，配套物理延音踏板功能，实现真实钢琴的延音音效与演奏逻辑
- 支持双操作模式：键盘按键绑定实时弹奏、UI界面滚轮滑动快速切换琴键，适配不同玩家操作习惯
- 自研音符粒子渲染系统，实现弹奏音符的位置实时跟随、动态特效渲染，大幅提升演奏沉浸感
- 完整的音效衰减、声道分离算法，还原真实空间音频效果

### 🎼 全自动乐谱播放系统
- 原生适配 `.nbs` 主流乐谱文件格式，支持玩家自定义导入外部乐谱文件
- 实现完整的乐谱解析、轨道映射、自动演奏逻辑，兼容90%以上的社区主流乐谱资源
- 支持播放进度控制、速度调节、轨道静音等进阶功能，满足玩家音乐创作与展示需求

### 🎛️ 唱片机远程集中控制系统
- 完全重写原版唱片机核心工作逻辑，不破坏原版基础功能的前提下实现能力扩展
- 基于红石信号系统实现唱片机与控制器的绑定，支持单控制器对多台唱片机的集中管理
- 实现远程开关、曲目切换、音量调节等核心功能，彻底解决原版需逐个手动操作的低效问题
- 完全兼容原版红石电路规则，可无缝融入玩家现有红石建筑与自动化系统

## 🚀 快速安装
### 环境要求
| 依赖项 | 版本要求 |
|--------|----------|
| Minecraft  Java版 | 1.20.1 |
| Minecraft Forge | 47.1.0 及以上 |
| Java 环境 | 17 及以上 |

### 安装步骤
1. 安装对应版本的 Minecraft Forge 加载器
2. 前往本仓库 [Releases](https://github.com/WitcherBB/BetterSound/releases) 页面下载最新稳定版模组 `.jar` 文件
3. 将下载的模组文件放入 Minecraft 游戏目录下的 `mods` 文件夹
4. 启动游戏，在模组列表中确认 BetterSound 已成功加载，即可开始使用

## 📖 详细使用指南
### 钢琴使用说明
1. **获取方式**：在游戏内创造模式物品栏的「更好的声音」分类中，可直接获取钢琴、琴凳、踏板物品
2. **放置方式**：将钢琴放置在地面，配套放置琴凳与踏板，形成完整演奏单元
3. **基础操作**：
    - 右键点击钢琴即可打开演奏UI界面
    - 鼠标点击琴键/键盘绑定按键即可弹奏，滚轮滑动可快速切换音区
    - 踩下踏板可触发延音效果，松开后延音停止
4. **乐谱播放**：在UI界面导入 `.nbs` 乐谱文件，点击播放按钮即可启动自动演奏，支持暂停、进度调节、速度修改

### 唱片机控制器使用说明
1. **获取方式**：创造模式物品栏中获取唱片机远程控制器物品
2. **绑定操作**：手持控制器右键点击需要管理的唱片机，即可完成绑定，支持绑定多台唱片机
3. **远程控制**：手持控制器右键点击空白处，打开集中控制界面，可对已绑定的所有唱片机进行批量开关、曲目切换、音量调节
4. **红石联动**：控制器支持接收红石信号触发预设操作，可无缝接入自动化红石系统

## ⚙️ 技术实现架构
### 核心技术栈
`Java` | `Minecraft Forge API` | `Mixins 字节码注入` | `游戏粒子渲染系统` | `面向对象编程(OOP)` | `Git 版本控制`

### 模块化架构设计
基于面向对象思想，将整个项目拆分为三大高内聚、低耦合的核心模块，模块间通过标准化接口交互，便于后续扩展与维护：

| 核心模块 | 模块职责 | 核心技术实现 |
|----------|----------|--------------|
| 钢琴核心模块 | 负责钢琴音效系统、按键映射、乐谱解析、自动演奏核心逻辑 | 基于OOP封装钢琴对象、音域映射算法、.nbs文件格式解析器、多轨道音频调度器 |
| UI交互模块 | 负责钢琴演奏界面、唱片机控制界面、玩家输入事件处理 | Forge GUI 框架、键鼠事件监听与分发、UI状态同步机制 |
| 渲染与世界交互模块 | 负责音符粒子渲染、方块实体渲染、红石信号处理、方块状态管理 | Minecraft 粒子系统、Tick 事件调度、Mixins 字节码注入、红石信号兼容处理 |

### 关键技术难点与解决方案
1. **原版唱片机逻辑重写与兼容性保障**
    - 难点：不破坏原版功能的前提下扩展能力，同时兼容原版红石规则
    - 方案：通过 Mixins 字节码注入技术对原版唱片机类进行非侵入式扩展，新增绑定与控制逻辑，保留原版全量接口，实现100%兼容原版行为

2. **全音域钢琴的音频与性能平衡**
    - 难点：88键独立音效同时播放的性能开销，以及空间音频的还原度
    - 方案：实现音效池复用机制，优化音频加载与释放逻辑；基于玩家位置与朝向实现声道分离与音量衰减算法，兼顾音效效果与游戏性能

3. **乐谱格式的高兼容性适配**
    - 难点：社区.nbs乐谱版本多、格式差异大，存在兼容性问题
    - 方案：自研多版本兼容的.nbs文件解析器，实现格式自动识别、异常数据容错处理，覆盖90%以上的社区主流乐谱资源
